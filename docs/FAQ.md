# FAQ

### Is this another ImGui designer that generates code once and forgets about it?

No. The project file is the source of truth, exports are deterministic, and hand edits go
back into the project through marked regions. You can keep re-exporting for as long as the
app lives.

### What do I have to ship from ImForge?

At most two headers: `imb_runtime.h` (ImGui-only) if you use animations or effects, and one
`fx/imb_fx_<backend>.h` if you use the shader blur. Everything else compiles out.

### Does it inject into games, hook Present/SwapBuffers or touch anti-cheat?

No. There's no injector, no hooks and no detection-evasion code of any kind; it's a UI tool.
Your app already renders ImGui, and the client header draws inside that frame. Don't ship
builds with `IMFORGE_LIVE` defined.

### Which ImGui versions work?

1.85 and newer, on `master` and `docking`. Features that need newer API are gated by
version, and the wizard shows what isn't available for your target. The builder itself uses
a pinned docking release.

### My project is on 1.85 with exceptions and RTTI turned off. Will the client compile?

Yes. Every header under `include/imforge/` has to build that way.

### Can two people work on the same project?

Yes. There's one JSON file per panel, component and theme, with sorted keys and stable ids,
so git diffs stay small and merge conflicts are rare.

### Can I use my own widgets?

Yes, by writing a `.imw.json` manifest for them, see [WIDGET_SDK.md](WIDGET_SDK.md). The
essentials pack is built the same way.

### How does live attach find my variables?

Through a reflection table, either generated by `imforge-reflect` (libclang) or written with
`IMFORGE_REFLECT(Type, fields...)`. Release code accesses members directly and has no table.

### Do I have to type a pairing code to connect?

No. The builder writes a one-time code to a file only your user can read and the app picks
it up automatically. You only copy a code by hand when the app can't read that file, for
example when it runs in a VM. See [LIVE_ATTACH.md](LIVE_ATTACH.md).

### I edited generated code outside a user region. Will I lose it?

No. If the edit only changed literals (a label, a size, a flag) it's read back into the
project. Otherwise it shows up in the Conflicts panel and you decide whether to keep it (the
block becomes locked) or regenerate.

### Why TCP by default and not shared memory?

TCP works the same on both operating systems and across a VM boundary, which comes up a lot
when the target only runs in a VM. Pipes and shared memory are there when you want them.

### Does the blur work if my game uses DX12 or Vulkan?

Yes, with the matching header. On those two backends `PrepareFrame` needs the frame's
command list or render pass info; the sample apps show the exact calls.

### Why C++17 for the builder when my project is C++14?

The builder is a separate program. Generated code and the client header follow the C++
standard you pick in the wizard (14, 17 or 20).

### Will there be macOS support?

Eventually, after v1. SDL3 + OpenGL 3 already builds there, but it's untested and not
supported today.
